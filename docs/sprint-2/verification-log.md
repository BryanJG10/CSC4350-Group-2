## Problems found and fixed during verification

1. **Previous e2e failure — dropdown labels.** `<select>` was nested inside its `<label>`, so the
   accessible name included every option ("Station All stations Grill…"). Fixed by pairing a separate
   `<label htmlFor>` with the select's `id` (`components.tsx → Select`).
2. **Keyboard focus after a missing rating.** Submitting without a rating moved focus to the error
   box instead of the rating radios, so arrow keys did nothing. Found during manual testing; fixed in
   `pages/Review.tsx`; regression assertion added to `App.test.tsx` and confirmed to fail without the fix.
3. **Dangling data references.** The catalog schema now rejects stations/items/reviews pointing at
   missing records (prevents a crash if a future API response is inconsistent); unit test added.
4. **Test race on WebKit.** The menu test typed a new date before the previous reset finished; it now
   waits for the reset first.

## Known gaps (not hidden)

- **Firefox not verified.** Playwright's Firefox (`firefox-1555`) fails to launch on this machine:
  `spawn UNKNOWN` / "side-by-side configuration is incorrect" (Windows runtime missing). Needs the
  Microsoft Visual C++ Redistributable or a run on another machine/CI.
- **WebKit ≠ Safari.** Playwright's Windows WebKit build cannot Tab to links and has no native date
  picker, so on WebKit the test skips link-tabbing and opens the dated menu by URL. Real Safari on macOS
  has not been tested.
- The `mobile-chrome` project is desktop Chrome at 390×844 with touch emulation, not a physical phone.
